# 発光 (Glow) フィルタ リバースエンジニアリング解析

対象: `data/exedit.auf`(AviUtl 拡張編集の標準フィルタプラグイン)、32bit PE、
`ImageBase = 0x10000000`。以下のアドレスはすべて VA(`RVA = VA - 0x10000000`)。

## 再現方法

すべてのスクリプトは本プロジェクトの `main.py` を踏み台にして実行する。
`main.py` はコマンドラインで指定されたスクリプトに対して、DLLパス
(デフォルト `data/exedit.auf`)とヘッダー一覧(デフォルト `data/filter.h`)を
渡す役割を持つ。

```
uv run main.py inspect/glow/<script>.py
uv run main.py tools.<tool>            # エフェクト非依存の共通ツール。一覧はリポジトリ直下の README
```

| スクリプト | 確認していること |
|---|---|
| `tools.filter_table --name 発光` | `FILTER_DLL` 配列(先頭 `0x100a3e28`)をたどり、`発光` の2つの登録エントリ・トラックバー定義・チェックボックスを抽出。両方とも `func_proc = 0x10053100` を共有 |
| `decompile_glow.py` | `0x10053100` 周辺に絞った `CFGFast` + angr デコンパイルで全体の呼び出し構造を把握(浮動小数点部分はリフトできないので以降のスクリプトで補う) |
| `disasm_params.py` | `強さ`/`しきい値` のマジックナンバー除算と、`拡散` の `pow()` 引数(定数 `0.5`, `0.2`)を実値でデコード |
| `verify_strength_threshold.py` | 上記の除算命令列を Python で再実装し raw=0~2000 の全2001通りが `raw*4096//1000` と一致することを確認 |
| `verify_mode_mapping.py` | `fp->flag & 0x20` の2分岐がそれぞれ触るバッファ・画素ストライドから、どちらがオブジェクト効果でどちらがフレームフィルタかを確定 |
| `verify_extract_alpha.py` | 明部抽出4種の式。オブジェクト側だけ輝度に**アルファを掛けてから**しきい値と比較していること、光色指定時は光色のYが輝度に掛かること |
| `verify_blur_chain.py` | 6パスが ping-pong で**連鎖**していること、1本目が垂直・2本目が水平でそれぞれ h/2-1・w/2-1 で半径がクランプされること |
| `verify_accumulate.py` | 蓄積が単純加算ではないこと。`拡散速度=0` は輝度8192で頭打ち＋色差フェード、`拡散速度>0` は float 無クランプ＋色差バイトの毎パスクランプ |
| `verify_diffusion_speed_boxsum.py` | `拡散速度>0` 用の縮小精度ワーカーも一様重みのボックス平均であること(ガウシアン核はどこにも無い) |
| `disasm_diffusion_speed.py` | `拡散速度` の順変換/逆変換の式と全浮動小数点定数 |
| `verify_curve_clamp.py` | 順変換は pow の前に y を [0,4096] にクランプし、逆変換は**クランプなしで16bit書き戻し**すること |
| `disasm_color.py` | `光色の設定` の `ex_data`(4バイト)の構造と、bit24 による抽出ワーカーの呼び分け |
| `verify_ycbcr_matrix.py` | 光色の RGB→YCbCr 係数テーブル(Q14)が ITU-R BT.601 フルレンジと一致すること |
| `verify_object_composite.py` | オブジェクト版の最終合成がアルファ加算＋アンプリマルチプライであること(単純加算ではない) |
| `simulate_glow_reference.py` | 上記すべてを織り込んだ整数忠実リファレンス実装。平坦領域の内部値を解析的に計算して最終RGBを出す |

## 1. 2つの登録エントリとモードの違い

`発光` は `FILTER_DLL` として2回登録されており、どちらも `func_proc = 0x10053100`
を共有する。実行時の分岐は `fp->flag & 0x20` の1点のみで、**画素フォーマットが
そもそも違う**(`verify_mode_mapping.py`)。

| | オブジェクトのフィルタ効果 | フレーム(映像)フィルタ |
|---|---|---|
| `FILTER_DLL` | `0x100a6218`、`flag=0x20` | `0x100a6340`、`flag=0x00` |
| チェックボックス | `光色の設定`, `サイズ固定` | `光色の設定` のみ |
| 入力画像 | `*(fpip+0xAC)` | `fpip->ycp_edit` (`+4`) |
| 画素形式 | **8バイト/画素 PIXEL_YCA**(y, cb, cr, **a**) | 6バイト/画素 PIXEL_YC(アルファなし) |
| 行幅 | `*(fpip+0xEC)` [画素] | `fpip->max_w` (`+0x14`) [画素] |
| 幅・高さ | `*(fpip+0xB4)` / `*(fpip+0xB8)` | `fpip->w` (`+0xC`) / `fpip->h` (`+0x10`) |
| 発光元バッファ | `fpip->ycp_temp` (`+8`)、6バイト/画素 | 同左 |
| 蓄積バッファ | `*(fpip+0xB0)`、6バイト/画素 | `拡散速度=0`: `ycp_edit` に直接 / `>0`: `*(fpip+0xB0)` |
| 明部抽出 | `sub_100535a0` / `sub_100536d0` | `sub_100533c0` / `sub_100534b0` |
| ぼかし2本目 | `sub_100544a0` (`拡散速度=0`) | `sub_100540a0` (`拡散速度=0`) |
| 最終合成 | `sub_10053890`(常に実行) | `sub_10053800`(`拡散速度>0` の時だけ) |

`flag=0x20` 側だけが `サイズ固定` を持ち、そのチェックが外れているときに
exedit 共有の「オフスクリーン描画」ルーチン(`0x1008a520`)でキャンバスを
広げてから処理する(方式C、[`canvas_growth.md` §4](../common/canvas_growth.md))。
発光がオブジェクトの外へにじむ分だけキャンバスを拡張する必要があるのは
オブジェクト側だけなので、この点でも `flag=0x20` = オブジェクト効果で整合する。
拡張後のサイズが `*(fpip+0x14)` / `*(fpip+0x18)`(最大サイズ)を超える場合は
何もせず返る。

## 2. パラメータ変換(`func_proc` 内、フレームごとに1回)

トラックバーは `fp->track[]` の順に `強さ`(初期値1000、範囲0~2000)、
`拡散`(250、10~2000)、`しきい値`(800、0~2000)、`拡散速度`(0、0~60)。

UI に表示される数値との対応は、登録構造体 `+0x74` にある exedit 独自の拡張
ブロック(表示スケール / スライダーのドラッグ下限・上限)で決まる。ブロックの
構造は [`inspect/common/param_scaling.md`](../common/param_scaling.md) 参照:

| トラックバー | 表示スケール | UI表示範囲 | スライダーで届く範囲 |
|---|---|---|---|
| `強さ` | 10 | 0.0~200.0 | 0.0~200.0 |
| `拡散` | 1 | 10~2000 | 10~800 |
| `しきい値` | 10 | 0.0~200.0 | 0.0~200.0 |
| `拡散速度` | 1 | 0~60 | 0~60 |

つまり `強さ` と `しきい値` は**UIの数値を10倍したものが生値**で、初期値の
`100.0` / `80.0` がそれぞれ生値 1000 / 800 にあたる。以下に出てくる
「`raw * 4096 / 1000`」は、UI表示で言えば**100.0% で満輝度 4096**という意味に
なる。`拡散` と `拡散速度` は UI の数値がそのまま生値。

以下、`func_proc` がその生値に対して行う変換:

* **`強さ`・`しきい値`(同じ変換)**: どちらも `raw * 4096` を全エフェクト共通の
  マジックナンバー除算 `0x10624dd3`([`param_scaling.md` §2](../common/param_scaling.md))
  にかける。**四捨五入ではなく0方向への切り捨て**:
  ```
  fixed = trunc(raw * 4096 / 1000)     // raw=1000 -> 4096 = 満輝度
  ```
  `raw*4096//1000` と全2001通りで一致することを確認済み
  (`verify_strength_threshold.py`)。
  * `強さ`側は 4096 でクランプされ、超過分は掛け算ではなく**別枠の定数オフセット**
    (overflow)として保持され、抽出時に「しきい値超え量 × ゲイン」へ**加算**される。
    つまり100%超では、明るい部分がより明るくなるだけでなく、しきい値ぎりぎりの
    暗い部分まで底上げされて光り出す。raw=2000 では overflow がちょうど4096に
    なるため、しきい値をわずかでも超えた画素は即座に最大輝度になる。
  * `しきい値`側はクランプされない(raw=2000 で fixed=8192 と満輝度4096を超え、
    その場合どの画素も超えられなくなるだけ)。
* **`拡散`**: `/1000` 変換は一切されない。生の整数のまま `fild` され、半径計算に
  直接使われる(手順4)。
* **`拡散速度`**: 生値をそのまま保持し、使う直前に 1~100 にクランプされる(手順5)。

## 3. 明部抽出

`EXFUNC::exec_multi_thread_func`(`exfunc+0xCC`)経由のマルチスレッド1パスで、
入力画像から発光元バッファ(`ycp_temp`)を作る。式は4ワーカー共通:

```
y_eff      = (src.y * src.a) >> 12        // オブジェクト効果のみ。フレーム版は src.y
diff       = y_eff - threshold
brightness = 0                                              (diff < 0)
           = min(((diff * gain) >> 12) + overflow, 4096)    (それ以外)
```

**輝度だけがアルファ加重で、色差は素の値を使う**という非対称がある
(`verify_extract_alpha.py`)。出力は `光色の設定`(`ex_data` bit24)で切り替わる:

* **bit24 セット = 色指定なし(既定)** → `sub_100535a0` / `sub_100533c0`
  ```
  out.y  = brightness
  out.cb = (src.cb * brightness) >> 12
  out.cr = (src.cr * brightness) >> 12
  ```
  元画素の色味を保ったまま明るさだけを間引く。赤いハイライトは赤く光る。
* **bit24 クリア = 色を指定済み** → `sub_100536d0` / `sub_100534b0`
  ```
  out.y  = (colorY  * brightness) >> 12
  out.cb = (colorCb * brightness) >> 12
  out.cr = (colorCr * brightness) >> 12
  ```
  元画素の色味は一切参照しない。**輝度にも光色のYが掛かる**点に注意 ―
  暗い光色(例: `#f00` は Y=0.299)を選ぶと、同じ設定でも発光そのものが
  比例して暗くなる。この輝度は後段でアルファ(手順6)にも指数の肩(手順5)にも
  なるため、この係数を後から掛けるのでは結果が一致しない。

## 4. 反復的な拡散(ぼかし)― `拡散` の使われ方

発光元バッファに対して固定で **6パス** のループが回る。各パスの半径は:

```
k      = pow(拡散raw * 0.5, 0.2)     // 事前に1回だけ計算
accum  = 2.0
for pass in 0..5:
    radius[pass] = round(accum)      // 四捨五入(+0.5 して切り捨て)
    accum *= k
```

`2.0 * k^5 = 拡散raw` になるように指数 `0.2` が選ばれており、**半径は 2px から
`拡散` の生値まで等比数列的に増加する**。1回の巨大なぼかしの代わりに小→大の
6段階を重ねる、いわゆるマルチスケール手法。

1パスは2ステップからなり(`sub_10053a30` がディスパッチ)、どちらも
**一様重みのボックス平均**(窓内の単純和 ÷ カーネル幅、カーネル幅 = 半径*2+1)。
ガウシアン核はどこにも無い ―― 全エフェクト共通の性質([`box_blur.md` §2](../common/box_blur.md))
で、通常精度版・縮小精度版のどちらでも成り立つことを確認済み
(`verify_blur_chain.py` / `verify_diffusion_speed_boxsum.py`)。

| | 通常精度(`拡散速度=0`) | 縮小精度(`拡散速度>0`) | 動作 |
|---|---|---|---|
| ステップ1(垂直) | `sub_10053b10` | `sub_10053da0` | `ycp_temp` → グローバルスクラッチ `0x101a5328`。半径は `h/2-1` でクランプ |
| ステップ2(水平) | `sub_100540a0` / `sub_100544a0` | `sub_100548a0` | スクラッチ → `ycp_temp` に書き戻し、**同時に蓄積バッファへ加算**。半径は `w/2-1` でクランプ |

ステップ2が `ycp_temp` に書き戻す先は、次のイテレーションのステップ1が読む場所
そのものなので、**パスN+1はパスNでぼけた結果をさらにぼかす(連鎖)**。同時に
各パスの結果が蓄積バッファへ足し込まれるため、最終的な発光は
「6段階それぞれのぼかし結果の合成」になる。

### 蓄積は単純加算ではない(`拡散速度=0`)

ステップ2の蓄積は次の飽和付き加算になっている(`verify_accumulate.py`):

```
s = acc.y + pass.y
if s <= 0x2000:   acc.y = s
                  acc.cb += pass.cb;  acc.cr += pass.cr
else:             acc.y = 0x2000                        // 輝度は8192(満輝度の2倍)で頭打ち
                  if s > 0x4000:  acc.cb = acc.cr = 0    // 色差を完全に捨てる
                  else:           t = 0x4000 - s
                                  acc.cb = ((acc.cb + pass.cb) * t) >> 13
                                  acc.cr = ((acc.cr + pass.cr) * t) >> 13
```

つまり発光が 8192 を超えた時点で**それ以上明るくならず、代わりにパスごとに
色差が (16384-s)/8192 倍されて白へ退色していく**。フレームフィルタ版はこの蓄積
先が `ycp_edit`(元画像)そのものなので、元画像の画素値が初期値になる。

## 5. `拡散速度` ― 指数/対数空間でのぼかし

`拡散速度>0` のときだけ、6パスループの**前後に1回ずつ**全画面変換が入る
(ヘルパーは `ぼかし` の `光の強さ` と共有)。`拡散速度=0` ではこの変換自体が
スキップされ、通常のぼかしになる。式・底 `base` の計算・順変換/逆変換の詳細は
[`inspect/common/exp_log_curve.md`](../common/exp_log_curve.md) にまとめてある
(`disasm_diffusion_speed.py` / `verify_curve_clamp.py` が本エフェクトでの検算)。

`発光` は `ぼかし` と違い、curved 空間で6パスを**加算**する(蓄積バッファへ
`fadd` で足し込む)。`log_base(a+b) ≠ log_base(a) + log_base(b)` なので、
6個の値を指数空間で足してから1回だけ対数を取るのは、各パスを個別に往復させて
から線形空間で足すのとは数学的に別物になる。形としては `log(sum(exp(x_i)))`
(LogSumExp)に近く、`base` が1から離れるほど「6パスのうち最も明るい1パスの
寄与」が支配的になる ― AviUtl の説明文「光の拡散していく速さ」に対応する挙動。

実用上重要な帰結が2つある(`verify_curve_clamp.py`):

* 指数の肩に乗るのは**明部抽出の出力**(手順3)なので、`拡散速度` は単独の
  強さを持たない。`強さ`/`しきい値`/`光色のY` がその場所に与えた輝度が大きいほど
  `curved` が桁違いに増幅される。
* 逆変換の書き戻しにクランプが無いため、**発光バッファの輝度は 4096(満輝度)を
  平気で超える**(`ぼかし` の `光の強さ` は平均なので超えない ―
  [`exp_log_curve.md` §4](../common/exp_log_curve.md) の対比参照)。最終的な
  RGB変換でチャンネルごとにクリップされ、その結果「彩度がバイトクランプで
  頭打ちの赤い発光」が黄色として出る、といった色相のずれが生じる。

## 6. 合成

### オブジェクト効果版 `sub_10053890`(常に実行)

6バイトの蓄積バッファ(PIXEL_YC)を8バイトの画像(PIXEL_YCA)へ合成する。
**発光の輝度がそのままアルファになり、色はそれで割って正規化される**
(`verify_object_composite.py`):

```
a = dst.a
if a >= 4096:                     // 不透明 ― ここだけ単純加算(クランプなし)
    dst.y += g.y;  dst.cb += g.cb;  dst.cr += g.cr
elif a <= 0:                      // 完全透明
    na = g.y;  if na <= 0: 何もしない
    na = min(na, 4096)
    dst.y  = (g.y  << 12) / na
    dst.cb = (g.cb << 12) / na
    dst.cr = (g.cr << 12) / na
    dst.a  = na
else:                             // 半透明
    na = a + g.y;  if na <= 0: 何もしない
    na = min(na, 4096)
    dst.c = (dst.c * a + (g.c << 12)) / na      // y/cb/cr 共通
    dst.a = na
```

アルファの合成は通常の `a + b - a*b` ではなく**加算(その後4096でクランプ)**。
プリマルチプライド換算では透明部への寄与は蓄積値そのものと等価だが、
背景と重ねた時点で差が出る。また、アルファが飽和する境目は `g.y = 4096` で、
`g.y` には光色のY(手順3)が既に掛かっているため、暗い光色ほど halo が
透明なまま保たれる。

### フレームフィルタ版 `sub_10053800`(`拡散速度>0` の時だけ)

アルファが無いので3チャンネルの単純加算のみ。`拡散速度=0` のときは
ステップ2(`sub_100540a0`)が毎パス `ycp_edit` へ直接蓄積しているため、
ループ後の追加処理自体が不要で呼ばれない。

## 7. `光色の設定` の保存形式

`check_default = -1` のボタン(`data/filter.h` の通り、負の初期値を持つ
チェックボックスは実体がボタン)で、状態は**4バイトの `ex_data`** 1個に入る
(下位24bit = RGB、bit24 = 指定なしフラグ)。保存形式・変換ルーチン
(`sub_1006fed0` → `sub_1006f520`)・BT.601 係数の検算は `発光` と `閃光` で共有
なので [`inspect/common/rgb_ycbcr.md`](../common/rgb_ycbcr.md) にまとめてある
(`disasm_color.py` / `verify_ycbcr_matrix.py` が本エフェクトでの検算)。

`発光` は本プロジェクトで扱う他のフィルタと違って `func_WndProc` を持つ
(両エントリ共通で `0x10054c90`)が、やっているのはこのボタンのラベル文字列を
`"指定無し (元画像の色)"` / `"RGB ( %d , %d , %d )"` に書き換えることだけで、
`fp->track[]` は一切参照していない。トラックバーの数値表示は AviUtl 本体側の
汎用描画が担っており、その表示スケールは手順2の拡張ブロックで決まる。

## 9. 参照テーブル

`強さ` (`fixed = trunc(raw*4096/1000)`、4096でクランプ、超過分は overflow):

| raw | fixed(クランプ後) | overflow |
|---|---|---|
| 500 | 2048 | 0 |
| 870 | 3563 | 0 |
| 1500 | 4096 | 2048 |

`しきい値` (`fixed = trunc(raw*4096/1000)`、クランプなし): raw=500 → 2048、
raw=870 → 3563、raw=1500 → 6144。

`拡散` (6パスの半径列、`k=(raw*0.5)^0.2`、`accum=2.0` から
`radius=round(accum); accum*=k` を6回):

| raw | 6パス半径列 |
|---|---|
| 30 | `[2, 3, 6, 10, 17, 30]` |
| 50 | `[2, 4, 7, 14, 26, 50]` |
| 250 | `[2, 5, 14, 36, 95, 250]` |
| 500 | `[2, 6, 18, 55, 166, 500]` |
