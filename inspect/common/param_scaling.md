# トラックバーの生値・表示スケール・定数除算

UI に出ている数値と `fp->track[]` の生値、そして生値から内部の固定小数への
変換。**この対応は `func_proc` を読んでも出てこない** ―― どのエフェクトも
`fp->track[]` を生値のまま使うだけで、表示の整形には関与していないからである。
対応はコードではなく**テーブル**に入っている。

## 1. `+0x74` 拡張ブロック

`0x100a3e28` の配列が指す登録構造体は `data/filter.h` の `FILTER` より長く、
`+0x74`(SDK では `func_is_saveframe`)に exedit 独自ブロックへのポインタがある。
ブロックは `int*` 4本:

```
struct +0x74 -> {
    int *scale;       // [0] 表示スケール(生値をこれで割って表示)
    int *group;       // [1] 多成分コントロールのグループ化マーカー(単独なら NULL/0)
    int *drag_min;    // [2] スライダーのドラッグ下限
    int *drag_max;    // [3] スライダーのドラッグ上限
}
```

いずれも `int[track_n]`。実例(`モザイク`):

```
0x100a88cc (struct + 0x74) -> 0x100a8844
0x100a8844: 0x100a8840 -> int[1] = {  1}      表示スケール
            0x00000000                        グループ化(単独トラックバーなので NULL)
            0x100a8838 -> int[1] = {  1}      ドラッグ下限
            0x100a883c -> int[1] = {200}      ドラッグ上限
```

```
uv run main.py tools.track_scale                 # 全エフェクト
uv run main.py tools.track_scale --name <名前>   # 1エフェクト分
uv run main.py tools.track_scale --groups        # slot[1] の根拠を全件出力
```

スロット `[0]` がスケールであることは推測ではなく、**表示値が既知のフィルタで
検算できる** ―― `透明度`(スケール10、生値 0~1000 → 0.0~100.0)、
`拡大率`(スケール100、初期値10000 → 100.00)、`発光` の `強さ`(スケール10、
初期値1000 → 100.0)。いずれも一致する。

### slot[1] ―― グループ化マーカー

この枠が非ゼロなのは**多成分コントロールを構成するトラックバーだけ**で、必ず
「最後以外は `+1`、最後は `-(要素数-1)`」の形になる。

| 例                                            | 値               |
| --------------------------------------------- | ---------------- |
| `閃光` の `X`, `Y`                            | `+1`, `-1`       |
| `X`, `Y`, `Z` / `拡張色設定` の `R`, `G`, `B` | `+1`, `+1`, `-2` |
| 単独トラックバー                              | 常に 0           |

`モザイク` の解析時点では用途未確定だったが、`閃光` の `X`/`Y` で初めて非ゼロが
出て確定した(`tools.track_scale --groups` が全件の根拠を出す)。

## 2. マジックナンバー除算 `0x10624dd3`

生値から内部固定小数への変換は、**全エフェクトが同じ MSVC の定型命令列**を使う。
`0x10624dd3` を掛けて上位32bitを取り、`sar 6` する ―― 実質 `>>38` ―― に符号補正を
足したもので、意味は `/1000` である。

```
fixed = trunc(raw * 4096 / 1000)      // 強さ・しきい値の類
r     = trunc(範囲 * (1000 ± 縦横比) / 1000)   // 半径の類
```

**四捨五入ではなく0方向への切り捨て**であることが要点で、リファレンス実装を
Python で書くときに `//` を使うと負の入力で食い違う([`integer_semantics.md`](integer_semantics.md))。

| エフェクト   | 適用先                                | 検算                                     |
| ------------ | ------------------------------------- | ---------------------------------------- |
| `ぼかし`     | `範囲`×`縦横比` → 半径                | 全2,002,000通りで `trunc(x/1000)` と一致 |
| `境界ぼかし` | 同上(式まで完全に同一)                | 400万通り全数一致                        |
| `発光`       | `強さ` / `しきい値` → `raw*4096/1000` | raw=0~2000 の全2001通り                  |
| `閃光`       | `強さ` → `raw*4096/1000`              | 全1001通り                               |
| `拡散光`     | `強さ` → `raw*4096/1000`              | 全1001通り                               |
| `グロー`     | **`しきい値` だけ** → `raw*4096/1000` | 全2001通り                               |
| `クロマキー` | **無し**。3本とも生値のまま `<<7` / `*key_sat>>8` / 半径 | `func_proc` にもワーカーにも `0x10624dd3` が1つも無い |

**`グロー` の `強さ` はこの変換を受けない**。生値のまま保持され、以降は小さい
整数倍・整数除算しか受けない唯一の例外である(`func_proc` 全体を走査しても
`0x10624dd3` は `しきい値` 用の1個しか無い ―― [`グロー` §2](../glow/README.md))。

`4096` が満輝度(= UI の 100.0%)にあたるので、「`raw * 4096 / 1000`」は
**表示スケール10のトラックバーで 100.0 のとき Q12 の 1.0** という意味になる。

`閃光` にはもう1箇所、`*1000 / 250`(`sar edx, 4`)の形で現れる**単なる4倍**が
ある。キャンバス拡張量の計算で、-500k~500k の全域で `*4` と一致することを
確認済み([`閃光` §3](../glint/README.md))。

## 3. `raw == 0` の扱い

先頭トラックバーが 0 のときの挙動はエフェクトごとに違う。

| エフェクト   | 条件         | 動作                                                   |
| ------------ | ------------ | ------------------------------------------------------ |
| `ぼかし`     | `範囲 == 0`  | 即 `return`。画像に一切触れない                        |
| `閃光`       | `強さ == 0`  | 即 `return`。キャンバスも広がらない                    |
| `拡散光`     | `強さ == 0`  | 即 `return TRUE`                                       |
| `モザイク`   | `サイズ < 2` | 即 `return TRUE`(1px ブロックは恒等なので結果は正しい) |
| `境界ぼかし` | `範囲 == 0`  | **即 return しない**。`rx=ry=0` のままワーカーへ進む   |
| `グロー`     | `強さ == 0` **または** `拡散 == 0` | 即 `return 1`。**2つのトラックバーが独立に早期 return を持つ**唯一の例 |
| `クロマキー` | (トラックバーではなく) `ex_data.status != 1` | 即 `return 1`。**早期 return の条件がトラックバーでない**唯一の例。`色相範囲 = 0` でも `境界補正 = 0` でもワーカーは走る |

## 4. クランプの有無

| エフェクト | パラメータ | 上限                                                                                                          |
| ---------- | ---------- | ------------------------------------------------------------------------------------------------------------- |
| `発光`     | `強さ`     | 4096 でクランプ。**超過分は別枠の定数オフセット**として保持され、抽出時に加算される(100%超のオーバードライブ) |
| `発光`     | `しきい値` | クランプなし(raw=2000 で 8192。どの画素も超えられなくなるだけ)                                                |
| `拡散光`   | `強さ`     | raw の上限が1000なので 4096 を超えられない。オーバードライブ経路は**コード上に存在しない**                    |
| `閃光`     | `強さ`     | 同上。`T = max(0, 4096 - strength)` として使われる                                                            |
| `グロー`   | `強さ`     | クランプ以前に固定小数ですらない。生値がそのまま `(sum >> 4) * strength >> 10` の係数になる([`グロー` §4](../glow/README.md)) |
| `グロー`   | `しきい値` | クランプなし(raw=2000 で 8192)。`発光` と同じ                                                                |
