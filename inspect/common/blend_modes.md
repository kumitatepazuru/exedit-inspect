# 矩形転送・矩形クリアと合成モード

`fp+0x64` の関数テーブル経由で呼ばれる、エフェクト非依存の描画ルーチン2本と、
その最後の引数(モード語)の読み方。`閃光` の `前方に合成`/`後方に合成` も、
`ぼかし`/`拡散光` のキャンバス事前拡張も、入口はここ1箇所である。

解析の出どころは [`閃光` §8](../glint/README.md)。

## 1. 関数テーブル `0x100a41e0`

exedit は起動時(`0x100315a4`)に全エフェクト構造体の `+0x64`
(SDK では `hwnd`)へこのテーブルを書き込む
([`filter_registration.md` §4](filter_registration.md))。

| スロット | 実体 | 役割 |
|---|---|---|
| `table[0x44]` | `0x10081b40` | 矩形転送(合成つき) |
| `table[0x48]` | `0x10081f90` | 矩形クリア |

どちらも**このテーブル経由でしか参照されない**。負の x/y は幅・高さに畳み込む
(= 矩形指定)。

```
table[0x44](dst, dx, dy, src, sx, sy, w, h, opacity, mode)
table[0x48](dst, x, y, w, h, ..., flags)
```

## 2. モード語の分解 ―― 下位バイト = 画素サイズ、上位バイト = 合成関数

`table[0x44]` は最後の引数を2つに割って読む。

```
0x10081cd9: mov ecx, [ebp+0x2c]              ; mode(第10引数)
0x10081cdc: sar ecx, 0x18                    ; >> 24。負値と 0x20 以上は 0 に落とす
0x10081d00: mov eax, [ecx*4 + 0x1009fbb0]    ; ブレンド関数を選ぶ
0x10081d15: cmp ecx, 0x13                    ; 0x13 だけは memcpy の特例経路へ
```

**下位バイト**(画素サイズ):

| bit | 意味 | 書き込み先 |
|---|---|---|
| bit0 | 転送**元**が8バイト画素 | `[0x102308e0]` へ 8 / 6 |
| bit1 | 転送**先**が8バイト画素 | `[0x10230918]` へ 8 / 6。既定のクリップ矩形も最大キャンバス/フレームで切り替わる |
| bit2 (`test bl,4`) | 代替クリップ矩形(`0x101e9edc` 系)を選ぶ | **未確定** |
| bit4 (`test bl,0x10`) | 代替クリップ矩形(`0x101ec840` 系)を選ぶ | **未確定** |

**上位バイト**はそのままブレンド関数テーブル `0x1009fbb0`(32エントリ)の添字。

## 3. ブレンド関数テーブル `0x1009fbb0`

読んだのは3エントリだけ。

| モード語 | 添字 | 関数 | 実体 | 使っているエフェクト |
|---|---|---|---|---|
| `0x11000003` | `0x11` | `0x1000ae90` | **加算合成** | `閃光` の `前方に合成` |
| `0x00000003` | `0x00` | `0x10007df0` | **通常合成**(src over dst) | `閃光` の `後方に合成` / `縁取り` の最終合成 |
| ―           | `0x02` | `0x100081e0` | 減算合成(**本体は未読**)。負に落ちた輝度の後始末が `シャープ`/`色調補正` と同じ定型 | [`luma_undershoot.md`](luma_undershoot.md) |
| `0x13000003` | `0x13` | `0x1000afd0` | 単純コピー(`movdqu`/`rep movsw` の特例経路) | `ぼかし` / `拡散光` のキャンバス転送、`シャープ` の元画像退避 |

```
0x1000ae90 (加算) : out_a = a_d + a_s - a_d*a_s
                    out_c = (c_d*a_d + c_s*a_s) / out_a
0x10007df0 (通常) : out_a = a_d + a_s - a_d*a_s
                    out_c = (c_s*a_s + c_d*a_d*(1 - a_s)) / out_a
```

加算側には `(1 - a_s)` の減衰項が無い ―― **転送先(=光のバッファ)が転送元の
アルファで薄まらない**。アルファはどちらも和集合で、
`0x1000800 - (0x1000-a_d)*(0x1000-a_s)` を `>>12` して求める(`0x800` は丸め項)。

**クランプはどちらにも無い。** 両者が不透明な画素では加算側は素の
`add word ptr [ecx], ax` になり、16bit で折り返す。特殊分岐(両者不透明 →
`dst += src`、`a_d <= 0` → src をそのままコピー)はすべて上の式の極限に一致する。

つまり `閃光` の `前方`/`後方` は**描画順の違いではなく、合成式そのものの違い**
である(向きはどちらも「光のバッファへ元オブジェクトを描く」で同じ)。

```
uv run main.py tools.disasm --addr 0x10081b40 --size 0x1c0   # モード語の分解
uv run main.py tools.disasm --addr 0x1000ae90 --size 0x100   # 加算合成
uv run main.py tools.disasm --addr 0x10007df0 --size 0xe0    # 通常合成
```

## 4. `table[0x48]` ―― 矩形クリア

`ぼかし` / `拡散光` / `グロー` の事前拡張経路が、新キャンバスを埋めるのに使う。
渡しているフラグは `2` で、**bit1 = 転送先が8バイト画素**と読める
(`table[0x44]` の下位バイトと同じ意味づけ)。残りのビットは未確定。

**「クリア」は0埋め専用ではない。** 引数6〜9がそのまま塗る画素の
`(y, cb, cr, a)` になる ―― `0x10082059`〜`0x10082082` が4つの int16 を
`0x102308ec`〜`0x102308f2` の塗りパターンへ順に書き込む。`ぼかし`/`拡散光`/
`グロー` の事前拡張は `(0,0,0,0)` を渡すので完全に透明になるが、`グロー` は
発光の蓄積バッファを `(0, 0, 0, 0x1000)` = **不透明な黒**で埋める
(`0x1005516e`)。この違いが `光成分のみ` の挙動そのものになっている
([`グロー` §8](../glow/README.md))。

| 引数 | 意味                     |
| ---- | ------------------------ |
| 1    | 転送先バッファ           |
| 2, 3 | x, y                     |
| 4, 5 | 幅, 高さ                 |
| 6    | 塗る `y`                 |
| 7    | 塗る `cb`                |
| 8    | 塗る `cr`                |
| 9    | 塗る `a`(6バイト画素では無視) |
| 10   | フラグ                   |

## 5. 呼び出し元一覧

| 呼び出し | モード語 | 目的 | 出典 |
|---|---|---|---|
| `ぼかし` 事前拡張 | `0x13000003` / `2` | 拡大バッファをクリアして元画像を中央へ | [`ぼかし` §5](../blur/README.md) |
| `拡散光` 事前拡張 | `0x13000003` / `2` | 同上(半径が画像に対して大きいとき) | [`拡散光` §4](../diffusion_light/README.md) |
| `閃光` 最終描画 | `0x11000003` / `0x00000003` | 光のバッファへ元オブジェクトを置き直す | [`閃光` §8](../glint/README.md) |
| `グロー` 事前拡張 | `0x13000003` / `2` | 同上(`2*拡散+1` がオブジェクトに収まらないとき) | [`グロー` §7](../glow/README.md) |
| `グロー` 蓄積準備 | ― / `2`(塗り色 `a=0x1000`) | 蓄積バッファを**不透明な黒**で埋める | [`グロー` §8](../glow/README.md) |
| `グロー` 抽出転送 | `0x13000003` | 抽出結果を蓄積バッファの `(rx, ry)` へ(`形状=通常` のみ) | [`グロー` §5.1](../glow/README.md) |
| `シャドー` パターン敷き詰め | `0x13000003` | 読み込んだパターン画像を影の箱の左上から**タイル状に**繰り返しコピー | [`シャドー` §6](../shadow/README.md) |
| `シャドー` 箱の外のクリア | ― / `2` | 影の箱の外(左・上・右・下の4矩形)を透明に。四隅は2回クリアされる | [`シャドー` §6](../shadow/README.md) |
| `シャープ` 元画像の退避 | `0x13000003` | 入力画像を丸ごとスクラッチ `[0x101a5328]` へ複製。**キャンバス操作ではなく save/restore** ―― 4パスの ping-pong で消える引き算の相手を取っておく | [`シャープ` §2](../sharp/README.md) |
| `縁取り` 事前パディング | `0x13000003` / `2` | カーネルより小さいオブジェクトを一時的に太らせる(方式Bの変種) | [`縁取り` §3](../border/README.md) |
| `縁取り` パターン敷き詰め | `0x13000003` | 同じタイル敷き詰め。ただし原点は**常にキャンバスの左上**(`(0,0)`) | [`縁取り` §6](../border/README.md) |
| `縁取り` 最終合成 | **`0x00000003`** | 縁の被覆マップの上に元オブジェクトを **src over** で重ねる | [`縁取り` §5](../border/README.md) |
| `縁取り` 削り戻し | `0x13000003` / `2` | 事前パディングぶんを切り出して元に戻す。**取り消す唯一の例** | [`縁取り` §3](../border/README.md) |
| `シャドー` 最終合成 | `0x00000003` | 影のキャンバスへオブジェクトを `(max(-X,0)+r, max(-Y,0)+r)` に通常合成 | [`シャドー` §3](../shadow/README.md) |

`閃光` の `光成分のみ`(mode=2)はこの描画自体をスキップする
(`jne` @ `0x1004e8ea`)。

キャンバス拡張そのものの流れは [`canvas_growth.md`](canvas_growth.md)。

## 6. 未確定事項

* **`0x1009fbb0` の残り29エントリ**。`0x01`〜`0x0c` が AviUtl の合成モード一覧
  (加算・減算・乗算…)に、`0x10` 番台がその内部用のアルファ対応版に対応して
  いそうだが未検証。未使用の添字(`0x0d`〜`0x0f`、`0x1a`〜`0x1f`)はすべて
  `0x00` と同じ `0x10007df0` を指す。
* **`table[0x44]` の第9引数(不透明度)**。`閃光` も `ぼかし` も 0 を渡し、関数側は
  `0x1000 - x` を `[0x10230900]` へ置く(`0x10081cd2`)。0 が不透明にあたるので
  透明度指定と見られるが、0 以外を渡す呼び出し元が無いため未検証。
* **下位バイトの bit2 / bit4 が選ぶ代替クリップ矩形**(`0x101e9edc` 系 /
  `0x101ec840` 系)が何を指すのか。
* **`table[0x48]` のフラグ `2` の残りのビット**。
