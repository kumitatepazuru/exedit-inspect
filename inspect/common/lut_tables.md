# 共有ルックアップテーブル `0x1006c680`

実行時に生成される三角関数テーブル3本。`境界ぼかし` の角丸め侵食で発見・導出
したものだが、**`境界ぼかし` 以外の複数のフィルタからも参照されている**
(生成ルーチンは exedit 全体の初期化コードの一部)。

出典: [`境界ぼかし` §3.1](../boundary_blur/README.md) / `verify_ease_table.py`

## 1. 3本のテーブル

`0x1006c680` が cos / sin / 1-cos で生成する。各 4097 要素の `int16` 配列
(`i = 0..4096`)。

| 先頭アドレス | 生成式 | 確認状況 |
|---|---|---|
| `0x101daf68` | cos 系 | 生成ルーチン内での分類のみ。**式は未検算** |
| `0x101dcf78` | `table[i] = trunc(2048 * (1 - cos(i * pi/4096)))` | `.rdata` の実定数から導出・検算済み |
| `0x101def80` | sin 系 | **式は未検算** |

## 2. `0x101dcf78` ―― イージングテーブル

0からなだらかに立ち上がり4096で頭打ちになる「持ち上げコサイン」型のイーズイン
カーブで、直線でも真円弧でもない。

| i | 0 | 1024 | 2048 | 3072 | 4096 |
|---|---|---|---|---|---|
| `table[i]` | 0 | 599 | **2047** | 3496 | 4096 |

中間点は理論値 2048 ちょうどのはずが、`cos(pi/2)` の浮動小数点誤差で **2047** に
なる(実測、実害なし)。

### 引き方は2通りあるが、配列は1本

```
順方向:  table[v]                    // v はそのまま 0~4096 の値
逆方向:  *(0x101def78 - 2*t)         // t は 0~4096 の比
```

`0x101dcf78 + 4096*2 == 0x101def78` が成り立つので、**逆方向参照は同じ配列の
`table[4096 - t]`(= 左右反転)に過ぎない**。アドレス演算だけで確認できる。

`0x101def78` はテーブル2の**末尾要素**(`table[4096]`)であって、テーブル3の先頭
`0x101def80` とは別物 ―― 8バイト手前にある。見間違えやすい。

## 3. 使われ方(`境界ぼかし` OFF パス)

縦横それぞれの「軸ランプ」(位置だけで決まる 0~4096 の直線)をテーブルに通し、
**ユークリッド和**を取る:

```
v = table[縦ランプ値]
h = table[横ランプ値]                             // 逆引きテーブル参照で実装
dist   = trunc(sqrt(v*v + h*h))                   // fild/fsqrt/切り捨て
alpha' = max(元のalpha - 2*dist, 0)
```

角では両軸の寄与が重なってより深く侵食され、辺の中央は片方の軸しか効かない ――
これが「辺は緩やかに、角は丸く縮む」角丸め侵食の正体。

## 4. 未確定事項

* **`0x1006c680` の呼び出し元**(いつテーブルが初期化されるか)。`境界ぼかし` の
  `func_init` は NULL なので、少なくともこのフィルタ自身がトリガーしているのでは
  なく exedit 全体の初期化経路のどこかから呼ばれていると考えられるが、具体的な
  呼び出し元は特定していない。
* **`0x101daf68` / `0x101def80` の正確な生成式と参照元**。cos / sin と分類しては
  いるが、`0x101dcf78` のように `.rdata` の実定数から導出したわけではない。
* **どのフィルタがこれらを参照しているか**の全件リスト。`tools.xrefs` で
  3アドレスを引けば出せるはずだが、まだやっていない。
