# キャンバス拡張と `サイズ固定`

オブジェクト効果は、効果がオブジェクトの外へにじむ分だけ外接矩形を広げられる。
広げ方が**エフェクトごとに4通りある**ので、`サイズ固定` の意味も一律ではない。

## 1. 共通の上限

| グローバル   | 中身                               |
| ------------ | ---------------------------------- |
| `0x10196748` | オブジェクトキャンバスの**最大幅** |
| `0x101920e0` | 同・**最大高**                     |
| `0x10178ec0` | **最大フレーム幅**                 |
| `0x101790c8` | 同・**最大フレーム高**             |

上の2つは `ぼかし`([§5](../blur/README.md))で同定し、
`閃光`([§3](../glint/README.md))が同じ番地を同じ意味で使っていることを確認済み。

下の2つは `グロー` のフレーム経路で出てくる([§1](../glow/README.md))。
矩形転送 `0x10081b40` と矩形クリア `0x10081f90` が**画素サイズで既定クリップ矩形を
切り替える**とき、8バイト画素なら `0x10196748`/`0x101920e0`、6バイト画素なら
`0x10178ec0`/`0x101790c8` を読む(`0x10081fbb` / `0x10081fd6`)ので、
オブジェクトキャンバスとフレームの対になっている
(`uv run main.py inspect/glow/verify_canvas_growth.py` 第5節)。
**書き込み側は未追跡**。

フレーム(映像)フィルタ版はキャンバスという概念を持たないので、拡張経路そのものは
持たない ―― `グロー` もフレーム版では拡張の代わりに半径をクランプする。

## 2. 方式A ―― ワーカー自身が枠外に書く

**`ぼかし`(`サイズ固定` オフ)/ `拡散光`(`サイズ固定` オフ)。**

専用のワーカーが出力を `2*半径` 行(列)分多く書き、`func_proc` が
`*(fpip+0xB4)` / `*(fpip+0xB8)` にその分を足す。同時に出力が半径分ずれるので、
オブジェクトは広がったキャンバスの中央に収まる。

- `ぼかし`: 4パスで各軸 `+2*(r_hi + r_lo) = +2*範囲`
- `拡散光`: 2ラウンドで各軸 `+2*(r1 + r2) = +2*拡散`(**片側 `拡散` 画素**)

`拡散光` はこの方式のために `func_proc` 側で3つの準備をする
([§4](../diffusion_light/README.md)):

- **クランプ**: `w + 拡散*4 > *(fpip+0xEC)` なら `拡散 = c_div(stride - w, 4)`。
  高さも `*(fpip+0xF0)` に対して同様。実際の成長は `2*拡散` なので4倍で抑えるのは
  倍の余裕を取った安全側の見積り。
- **1行だけのゼロクリア**: `*(fpip+0xAC)` と `*(fpip+0xB0)` の**1行手前**を
  `w + 拡散*4` 画素ぶんゼロで埋める。水平パスは出力行が元画像の外のとき
  この行を読み出し先にする(`0x1001cbb9`)ので、そこは完全に透明な画素と
  合成されて純粋な拡散光になる。読み取り専用なので1行で足りる。
- **`2r+1` 画素の横ずらし**: 垂直パスは出力を `dst + (2r+1 + x)*8` に書く
  (`0x1001c784`)。水平パスが**同じバッファ上でイン・プレースに**スライドする
  ため。ずらし量は `2r+1` より小さくできず、大きくすれば確保すべき余白が
  無駄に増える ―― 必要十分。

`ぼかし` 側の上限は最大キャンバスサイズだけで、`w + 2*rx > 最大幅` なら
`rx = (最大幅 - w)/2` に切り詰められる。

## 3. 方式B ―― `table` で先に広げてしまう(事前拡張)

**`ぼかし` / `拡散光` の、半径が画像に対して大きいとき。**

スライディングウィンドウの中段ループが `長さ - カーネル幅` 回なので、半径が
寸法の半分以上だと回数が0以下になって破綻する
([`box_blur.md` §4](box_blur.md))。そこで**先に広げてから、非拡張ワーカーを
拡大済みバッファ上で走らせる**。

```
table[0x48](B, 0, 0, w+2R, h+2R, ..., flags=2)          // 拡大サイズでバッファBをクリア
table[0x44](B, R, R, A, 0, 0, w, h, ..., 0x13000003)    // Aを中央へ転送
swap A/B;  w += 2R;  h += 2R;  ローカルの サイズ固定 := 1
```

| エフェクト | 発動条件                                                                     | R                    |
| ---------- | ---------------------------------------------------------------------------- | -------------------- |
| `ぼかし`   | `2*rx_hi >= w` / `2*ry_hi >= h` / `2*rx_lo >= w` / `2*ry_lo >= h` のいずれか | 軸ごとの `rx` / `ry` |
| `拡散光`   | `2*r1 >= w or h` / `2*r2 >= w or h`(`0x1001c45e`)                            | `r1 + r2 = 拡散`     |
| `グロー`   | `2*拡散+1 > w` / `2*拡散+1 > h`(`0x10054f20`)                                | `c_div(2*拡散+2-寸法, 2)`(軸ごと) |

`グロー` だけは、この事前拡張のあとに**さらに無条件で `+2*拡散`** される
(方式A相当だが、余白を作るのはワーカーではなく蓄積バッファのサイズである)。
つまり2回広がる ―― [`グロー` §7](../glow/README.md)。

**最終サイズはどちらの経路でも同じ**(`ぼかし` なら `(w+2rx, h+2ry)`、
`拡散光` なら片側 `拡散` 画素)。変わるのは**端の除数の扱いだけ**で、以降は
固定サイズ版ワーカーが走るので実サンプル数で割るようになる
([`box_blur.md` §3](box_blur.md))。

モード語 `0x13000003` / `2` の意味は [`blend_modes.md`](blend_modes.md)。

## 4. 方式C ―― オフスクリーン描画 `0x1008a520`

**`発光`(`サイズ固定` オフ)。**

exedit 共有の「オフスクリーン描画」ルーチンを `[0x100b8c60]` 経由で呼び、
広げてから処理する。拡張後のサイズが `*(fpip+0x14)` / `*(fpip+0x18)`
(`max_w` / `max_h`)を超える場合は**何もせず返る**
([`発光` §1](../luminous/README.md))。

## 5. 方式D ―― `func_proc` が矩形を計算して置き直す

**`閃光`。** 光条の到達距離から拡張後の矩形を直接組み立てる
([`閃光` §3](../glint/README.md))。

```
x0 = min(0, -3*cx)                  y0 = min(0, -3*cy)
x1 = max(0, 3*(w - cx))             y1 = max(0, 3*(h - cy))
x0, y0, x1, y1 = それぞれ (値 * strength) >> 12       // sar なので負値は floor
x1 += w ;  y1 += h
```

「4倍」は光線の到達距離そのもの ―― ある出力画素は中心へ向かって距離の75%を走査
するので、中心から距離 `d` のソース画素は `D = 4d` まで光を伸ばす。**キャンバスは
光条の端がちょうど収まる大きさで、1画素も余分ではない。**

拡張量が `strength` 倍される点は注意が要る。`強さ` は本来しきい値であって長さ
ではなく、**幾何的な到達距離は `強さ` に関係なく4倍のまま**である。「暗い先端は
どうせしきい値を超えないだろう」という前提でキャンバスだけが切り詰められている。

そのあと2つの上限で1画素ずつ削る:

```
while (x1 - x0) > 最大キャンバス幅 (0x10196748)
   || (x1 - x0) > fpip->w + 2*w :
    if (x0 < w - x1)  x0 += 1        // はみ出しが大きい側から削る
    else              x1 -= 1
```

最後にバッファを入れ替え、`+0xD4`/`+0xD8` にオブジェクト中心のずれを書き、
`+0xB4`/`+0xB8` を新サイズにする。

## 6. `サイズ固定` の意味はエフェクトごとに違う

| エフェクト         | `サイズ固定` オンのとき                                                                                                                                                  |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `ぼかし`           | キャンバス拡張も半径クランプも一切しない。**端で正規化し直す**ワーカーへ切り替わる。チェック自体は2回別の意味で読まれ、事前拡張経路はローカルコピーだけを 1 に書き換える |
| `拡散光`           | 拡張せず、**端の除数が実サンプル数になる**(= 端で拡散光が減衰しない)                                                                                                     |
| `発光`             | オフスクリーン描画を呼ばない                                                                                                                                             |
| `閃光`(`check[2]`) | 計算した矩形を全部捨てて `x0=y0=0, x1=w, y1=h` に戻す(`0x1004e860`)。**光線の計算自体は変わらない**ので、光条は同じように伸びようとしてオブジェクトの矩形で切られる      |

`境界ぼかし` と `モザイク` は `サイズ固定` を持たない ―― どちらもオブジェクトの
外へにじまないので、拡張の呼び出し自体がコード上に存在しない。

**`グロー` は外へにじむのに `サイズ固定` を持たない**唯一の例で、`拡散` を
上げれば必ず外接矩形が変わる。しかも拡張は方向に依存しないので、
`形状 = ライン(横)` のように横にしか光らない設定でも上下に `拡散` 画素の
透明な余白が付く([`グロー` §7](../glow/README.md))。

## 7. 未確定事項

- **`ぼかし` の `サイズ固定` オン + `範囲` が寸法の半分以上**。クランプも事前拡張も
  されない唯一の組み合わせで、画像外の読み出しと書き込まれない帯が生じる
  ([`box_blur.md` §4](box_blur.md))。
- **`+0xD4`/`+0xD8` の単位**。`閃光` の補正量の式から 1/4096 画素と推定している
  だけで、他エフェクトでの使われ方と突き合わせてはいない。
- **`0x1008a520` の中身**は読んでいない(`発光` からは呼び出しだけを確認)。
