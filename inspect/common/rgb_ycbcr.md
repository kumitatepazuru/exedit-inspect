# `光色の設定` と RGB→YCbCr 変換

`発光` と `閃光` が共有している色まわり。ボタンの保存形式・変換ルーチン・係数まで
同じで、**違うのは変換結果の使い方だけ**。

## 1. ボタンの保存形式

`光色の設定` は `check_default` が負の値のチェックボックス ―― `data/filter.h` の
言うとおり、負の初期値を持つチェックボックスは実体がボタンになる。状態は
`ex_data` に入る([`filter_registration.md` §5](filter_registration.md))。

| エフェクト | `ex_data_size` | レイアウト                                          |
| ---------- | -------------- | --------------------------------------------------- |
| `発光`     | 4              | `dword[0]`: 下位24bit = RGB、bit24 = 指定なしフラグ |
| `閃光`     | 8              | `color`(3) + `no_color`(1、= bit24)+ `mode`(4)      |

- 下位24bit = RGB(`R = byte0`, `G = byte1`, `B = byte2` ―― Win32 `COLORREF` と
  同じ並び)
- **bit24 (`0x1000000`) = 「指定なし(各ピクセル自身の色を使う)」フラグ**
- 新規追加時の既定値は bit24 セット + 未使用の白
  (`発光`: `0x01FFFFFF` / `閃光`: `ff ff ff 01 00 00 00 00`)

`閃光` の `mode`(4バイト)は `前方に合成` の3択で、色とは無関係
([`blend_modes.md`](blend_modes.md))。

## 2. 変換ルーチン

```
0x1006fed0  ―― ex_data の下位24bit を R/G/B に分解し、0x1006f520 を呼ぶ
0x1006f520  ―― 汎用 RGB→YCbCr(→ 0x1006f6e0 / 0x1006f5b0)
```

`0x1006fed0` は**毎フレーム、bit24 の状態に関係なく**呼ばれる。結果を使うか
どうかだけが bit24 次第。書き込み先はエフェクトごとに別:

| エフェクト | Y            | Cb           | Cr           |
| ---------- | ------------ | ------------ | ------------ |
| `発光`     | `0x101b2004` | `0x101b1ff4` | `0x101b1ffc` |
| `閃光`     | `0x101a6bac` | `0x101a6b90` | `0x101a6b9c` |

## 3. 係数は BT.601 フルレンジ

係数テーブル `0x100a989c` / `0x100a98a4` / `0x100a98ac`(Q14 固定小数点)は
**ITU-R BT.601 フルレンジと誤差 0.3% 以内で一致する**
(`verify_ycbcr_matrix.py`、[`発光` §7](../luminous/README.md))。

BT.601 の逆変換は係数が非対称:

```
R = Y + 1.402000*Cr
G = Y - 0.344136*Cb - 0.714136*Cr
B = Y + 1.772000*Cb
```

`Cb→B` の 1.772 に対し `Cr→G` は 0.714136 しかないため、赤い光が白地ににじんだ
ときに G と B が同じだけ減ることはない。

**最終的な YCbCr→RGB 変換とそのクリップは `aviutl.exe` 側**(本プロジェクトの
解析対象外)にあるので、逆変換も BT.601 だというのは順変換からの推定にとどまる。
これは全エフェクト共通の「未確定事項」である。

## 4. 使い方は正反対

|                      | `発光`                                                                         | `閃光`                                                                            |
| -------------------- | ------------------------------------------------------------------------------ | --------------------------------------------------------------------------------- |
| bit24 セット(既定)   | `out.c = (src.c * brightness) >> 12`。元画素の色味を保ったまま明るさだけ間引く | `sum += (src.y, src.cb, src.cr) * src.a >> 12`。各画素自身の色で光る              |
| bit24 クリア(色指定) | `out.c = (colorC * brightness) >> 12`。**輝度にも光色の Y が掛かる**           | `sum += (colorY, colorCb, colorCr) * src.a >> 12`。**ソースの輝度を一切読まない** |
| 測っているもの       | 抽出した明るさ × 指定色                                                        | 被覆率 × 指定色                                                                   |

`発光` は「指定色 × 抽出した明るさ」、`閃光` は「指定色 × 被覆率」。同じ形なら
明るいオブジェクトも暗いオブジェクトも同じように光るのが `閃光` である。

### 落とし穴 ―― 暗い光色は消える

どちらも**光色の Y が後段の分母や指数の肩に乗る**ため、暗い色を選ぶと効果自体が
弱くなる。

- `発光`: 光色の Y が輝度に掛かり、その輝度がアルファにも
  ([`発光` §6](../luminous/README.md))指数の肩にも
  ([`exp_log_curve.md`](exp_log_curve.md))なる。**この係数を後から掛けるのでは
  結果が一致しない。**
- `閃光`: 色指定時に到達しうる `avgY` の上限が**指定色自身の Y** なので、
  `T = 4096 - strength` がそれを超えていると**何も描かれない**。

| 光色      | 色の Y | `閃光` でこれを超える `強さ` が必要 |
| --------- | ------ | ----------------------------------- |
| `#ffffff` | 4095   | 0.1                                 |
| `#ffff00` | 3629   | 11.5                                |
| `#00ff00` | 2404   | 41.4                                |
| `#ff0000` | 1224   | 70.2                                |
| `#0000ff` | 466    | 88.7                                |
| `#000080` | 234    | 94.3                                |

暗い青の光は `強さ 88.7` 未満では、どんなに明るいオブジェクトに掛けても
まったく出ない。

## 5. `func_WndProc` がやること

`発光`(`0x10054c90`)も `閃光`(`0x1004f3f0`)も、色ダイアログを開いてボタンの
ラベルを `"指定無し (元画像の色)"` / `"RGB ( %d , %d , %d )"` に書き換えるだけで、
**`fp->track[]` は一切参照しない**。`閃光` はこれに加えて合成モードのコンボ
ボックスを `0x100a5c5c` から始まる cp932 文字列3つで構築する(`0x1004f4a0`)。
