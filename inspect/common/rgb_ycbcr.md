# `光色の設定` と RGB→YCbCr 変換

`発光` と `閃光` が共有している色まわり。ボタンの保存形式・変換ルーチン・係数まで
同じで、**違うのは変換結果の使い方だけ**。`ライト` も同じ変換ルーチンを使うが
**「指定なし」モード自体が存在しない**唯一の例で、§1 末尾で扱う。

## 1. ボタンの保存形式

`光色の設定` は `check_default` が負の値のチェックボックス ―― `data/filter.h` の
言うとおり、負の初期値を持つチェックボックスは実体がボタンになる。状態は
`ex_data` に入る([`filter_registration.md` §5](filter_registration.md))。

| エフェクト | `ex_data_size` | レイアウト                                          |
| ---------- | -------------- | --------------------------------------------------- |
| `発光`     | 4              | `dword[0]`: 下位24bit = RGB、bit24 = 指定なしフラグ |
| `閃光`     | 8              | `color`(3) + `no_color`(1、= bit24)+ `mode`(4)      |
| `グロー`   | 8              | `color`(3) + `no_color`(1、= bit24)+ `type`(4、`形状` コンボ) |
| `ライト`   | 4              | `dword[0]`: 下位24bit = RGB、**上位バイトは未使用のパディング** |
| `シャドー` | 260            | `color`(3) + パディング(1) + `file`(256、パターン画像のパス)  |

- 下位24bit = RGB(`R = byte0`, `G = byte1`, `B = byte2` ―― Win32 `COLORREF` と
  同じ並び)
- **bit24 (`0x1000000`) = 「指定なし(各ピクセル自身の色を使う)」フラグ**
- 新規追加時の既定値は bit24 セット + 未使用の白
  (`発光`: `0x01FFFFFF` / `閃光`: `ff ff ff 01 00 00 00 00`)

`閃光` の `mode`(4バイト)は `前方に合成` の3択で、色とは無関係
([`blend_modes.md`](blend_modes.md))。

**`シャドー` も同じで「指定なし」を持たない。** `+0x70` フィールド表
(`0x100b84b0`)の宣言は `color`(3バイト)+ パディング(1バイト)で、`ライト` と
同一の形。既定値は `ex_data_def` が全ゼロなので **RGB(0,0,0) の真っ黒**である
([`シャドー` §1](../shadow/README.md))。ただし `シャドー` には「色の代わりに
パターン画像を使う」という別のモードがあり、`ex_data+4` にパスが入っている間は
色が完全に無視される(§4末尾)。

**`ライト` は `発光` と同じ4バイトのレイアウトを持つが、`+0x70` フィールド表
(`0x100a722c`)が宣言しているのは `color`(3バイト)だけ**で、上位バイトに
対応する名前付きフィールドが無い。`func_proc` もその1バイトを一度も読まない
([`ライト` §1/§2](../light/README.md))ので、**bit24 は「指定なしフラグ」
ではなく単なる未使用パディング**であり、`ライト` に「各ピクセル自身の色で
光る」モードは存在しない ―― 常に `色の設定` で選んだ1色を使う。

## 2. 変換ルーチン

```
0x1006fed0  ―― ex_data の下位24bit を R/G/B に分解し、0x1006f520 を呼ぶ
0x1006f520  ―― 汎用 RGB→YCbCr(→ 0x1006f6e0 / 0x1006f5b0)
```

`0x1006fed0` は**毎フレーム、bit24 の状態に関係なく**呼ばれる。結果を使うか
どうかだけが bit24 次第。書き込み先はエフェクトごとに別:

| エフェクト | Y            | Cb           | Cr           |
| ---------- | ------------ | ------------ | ------------ |
| `発光`     | `0x101b2004` | `0x101b1ff4` | `0x101b1ffc` |
| `閃光`     | `0x101a6bac` | `0x101a6b90` | `0x101a6b9c` |
| `グロー`   | `0x101b2030` | `0x101b202c` | `0x101b202e` |
| `ライト`   | `0x101b20c0` | `0x101b20bc` | `0x101b20be` |
| `シャドー` | `0x102320b8` | `0x102320b4` | `0x102320b6` |

引数の並びは `sub_1006fed0(Y*, Cb*, Cr*, color)`。変換結果の3ワードを
`(out+0, out+2, out+4)` = `(Y, Cb, Cr)` の順に書き出すので、渡すポインタの
順番がそのまま意味になる(`0x1006ff0c`〜`0x1006ff20`)。

## 3. 係数は BT.601 フルレンジ

係数テーブル `0x100a989c` / `0x100a98a4` / `0x100a98ac`(Q14 固定小数点)は
**ITU-R BT.601 フルレンジと誤差 0.3% 以内で一致する**
(`verify_ycbcr_matrix.py`、[`発光` §7](../luminous/README.md))。

BT.601 の逆変換は係数が非対称:

```
R = Y + 1.402000*Cr
G = Y - 0.344136*Cb - 0.714136*Cr
B = Y + 1.772000*Cb
```

`Cb→B` の 1.772 に対し `Cr→G` は 0.714136 しかないため、赤い光が白地ににじんだ
ときに G と B が同じだけ減ることはない。

**最終的な YCbCr→RGB 変換とそのクリップは `aviutl.exe` 側**(本プロジェクトの
解析対象外)にあるので、逆変換も BT.601 だというのは順変換からの推定にとどまる。
これは全エフェクト共通の「未確定事項」である。

## 4. 使い方は正反対

|                      | `発光`                                                                         | `閃光`                                                                            | `グロー`                                                                     |
| -------------------- | ------------------------------------------------------------------------------ | --------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| bit24 セット(既定)   | `out.c = (src.c * brightness) >> 12`。元画素の色味を保ったまま明るさだけ間引く | `sum += (src.y, src.cb, src.cr) * src.a >> 12`。各画素自身の色で光る              | `out.c = c_div(src.c * b, src.y)`。**色差/輝度の比がそのまま残る**          |
| bit24 クリア(色指定) | `out.c = (colorC * brightness) >> 12`。**輝度にも光色の Y が掛かる**           | `sum += (colorY, colorCb, colorCr) * src.a >> 12`。**ソースの輝度を一切読まない** | `out.c = (colorC * (y - T)) >> 12`。同じく光色の Y が輝度に掛かる           |
| 測っているもの       | 抽出した明るさ × 指定色                                                        | 被覆率 × 指定色                                                                   | 抽出した明るさ × 指定色                                                     |

`グロー` は指定なし/指定ありで**カーブそのものが違う**のが特徴で、指定なしは
ソフトニー付きで漸近的に恒等写像、指定ありは素のヒンジ `y - T` になる
([`グロー` §3](../glow/README.md))。

`発光` は「指定色 × 抽出した明るさ」、`閃光` は「指定色 × 被覆率」。同じ形なら
明るいオブジェクトも暗いオブジェクトも同じように光るのが `閃光` である。

`ライト` は指定なしモードを持たない(§1)ので上の表に並ばないが、測っている
ものは `閃光` と同じ**被覆率**である ―― ただし被覆率の測り方が光線の
サンプリングではなく**アルファのボックス平均**で、後光パスは
`a = trunc(光色Y * scale / 4096)`、陰影パスは `out.c += (光色C * m) >> 12` と
いう形で光色を載せる([`ライト` §3/§4](../light/README.md))。

### 落とし穴 ―― 暗い光色は消える

どちらも**光色の Y が後段の分母や指数の肩に乗る**ため、暗い色を選ぶと効果自体が
弱くなる。

- `発光`: 光色の Y が輝度に掛かり、その輝度がアルファにも
  ([`発光` §6](../luminous/README.md))指数の肩にも
  ([`exp_log_curve.md`](exp_log_curve.md))なる。**この係数を後から掛けるのでは
  結果が一致しない。**
- `閃光`: 色指定時に到達しうる `avgY` の上限が**指定色自身の Y** なので、
  `T = 4096 - strength` がそれを超えていると**何も描かれない**。
- `グロー`: 抽出量が `(colorY * (y - T)) >> 12` なので、光色の Y が
  そのまま倍率になる。`#0000ff`(Y=466)では白の 1/9 の明るさしか出ない。
- `ライト`: **後光パスだけ**が同じ性質を持つ。出力アルファが
  `trunc(光色Y * scale / 4096)` なので、`scale` が上限の 4096 に達しても
  **アルファは光色の Y を超えられない** ―― `#0000ff`(Y=466)の後光は
  どれだけ `強さ` を上げても不透明度 11% 止まりになる。陰影パスのほうは
  加算なので影響を受けず、`光色C * m >> 12` を素直に足すだけである。

| 光色      | 色の Y | `閃光` でこれを超える `強さ` が必要 |
| --------- | ------ | ----------------------------------- |
| `#ffffff` | 4095   | 0.1                                 |
| `#ffff00` | 3629   | 11.5                                |
| `#00ff00` | 2404   | 41.4                                |
| `#ff0000` | 1224   | 70.2                                |
| `#0000ff` | 466    | 88.7                                |
| `#000080` | 234    | 94.3                                |

暗い青の光は `強さ 88.7` 未満では、どんなに明るいオブジェクトに掛けても
まったく出ない。

### 例外 ―― `シャドー` は素のまま格納する

`シャドー` だけはこの罠に**掛からない**。出力画素は
`{ Y = 影色Y, Cb = 影色Cb, Cr = 影色Cr, a = trunc(被覆率 * 濃さ) }` で、色は
アンプリマルチプライされず、アルファに載るのは被覆率と `濃さ` だけである。
したがって**真っ黒な影も真っ白な影と同じ不透明度になる** ―― 既定値が
RGB(0,0,0) である以上そうでなければ困る、という設計上の必然でもある
([`シャドー` §5](../shadow/README.md))。

「アルファに何を載せるか」の一覧にすると:

| エフェクト                | アルファに載るもの            | 暗い色の影響           |
| ------------------------- | ----------------------------- | ---------------------- |
| `閃光` / `ライト` の後光  | `光色Y × 被覆率`              | **効果が消える**       |
| `発光` / `グロー`         | (抽出量に `光色Y` が掛かる)   | **効果が弱くなる**     |
| `シャドー`                | `被覆率 × 濃さ` のみ          | **無し**               |

なお `シャドー` は `パターン画像ファイル` が設定されていると
`ex_data.color` を一切読まなくなる ―― 色は敷き詰めたパターンから来て、
影のアルファはパターン自身のアルファと掛け合わされる。

## 5. `func_WndProc` がやること

`発光`(`0x10054c90`)も `閃光`(`0x1004f3f0`)も `グロー`(`0x10058ea0`)も、
色ダイアログを開いてボタンのラベルを `"指定無し (元画像の色)"` /
`"RGB ( %d , %d , %d )"` に書き換えるだけで、**`fp->track[]` は一切参照しない**。
`閃光` はこれに加えて合成モードのコンボボックスを `0x100a5c5c` から始まる
cp932 文字列3つで構築し(`0x1004f4a0`)、`グロー` は `形状` のコンボボックスの
選択値(コマンド `0x1e1c` の `lParam`)を `ex_data.type` へ書き戻す。
